# 配信プラットフォームの考察

STAR FABLE をどこに置くか、置くと何が起きるかを整理したもの。
2026-08-08 時点の見立て。**数字はどれも概算**で、実測ではない。
本気で比べるときは Similarweb などで見直すこと。

## 上げかた(Cloudflare Pages)

**この 2 行を直に叩く。** `deploy-pages.bat dev` でも同じことをするが、
最後に `pause` が入っているので、自動で呼ぶと止まったまま返ってこない。

### DEV(確認用。`dev.msxpoi1.pages.dev`)

```
powershell -ExecutionPolicy Bypass -File build-deploy.ps1 -Local
npx -y wrangler@4 pages deploy deploy-local --project-name msxpoi1 --branch dev --commit-dirty=true
```

`-Local` は `dev: true` のまま固める。**シーン選択・`mmsxxDebug` などの
開発用の口が残る**ので、実機で中を覗きながら詰められる。
**難読化は掛けない**(掛けると覗けなくなる)。

**DEV は Cloudflare Access の内側**にある。上げたあとの目視は人がやること。

### 本番(`msxpoi1.pages.dev`)

```
powershell -ExecutionPolicy Bypass -File build-deploy.ps1 -Obfuscate
npx -y wrangler@4 pages deploy deploy --project-name msxpoi1 --branch main --commit-dirty=true
```

**`-Obfuscate` は必須**。素のまま上げないこと(付け忘れると開発用の口が
そのまま読める形で公開される)。出来るフォルダも ZIP も DEV とは別
(`deploy/` と `star-fable-deploy.zip`)。

## このゲームの性質(置き場所を選ぶ前提)

- **ビルドが要らない静的ファイルの塊**。フォルダごと静的ホスティングに置けば動く
- 依存ライブラリが実質ない(素の ES Modules)ので、**数年後でも動かせる**
- いまはキーボード操作が前提。**スマホ対応は作業中**
- ランキングは Cloudflare Workers の**1 台に集約**している

1 つめと 2 つめは、置き場所を増やすうえでも保全のうえでも効いてくる強みになる。
3 つめは、大手ポータルへ出すときの足かせになる。

| **Poki** | 同上、さらに大手。要求水準が高く、スマホ対応がほぼ前提 |
| **Coolmath Games** | 学校で遊ばれる巨大な客層。審査あり |

## トラフィックの見立て

大事なのは、**サイト全体の規模と、無名の新作が実際に得る数はまったく別**だということ。

| サイト | サイト全体(月間・桁) | 無名の新作が実際に得るもの |
|---|---|---|
| Poki | 1 億超 | **選ばれなければゼロ**。選ばれれば桁違い |
| CrazyGames | 1 億前後 | 同上。審査を通ること自体が関門 |
| Coolmath Games | 数千万〜1 億 | 同上 |
| itch.io | 1000 万〜2000 万 | **自分で連れてこないとほぼゼロ**。数十〜数百 |
| Newgrounds | 1000 万前後 | **新作は必ず一度人目に触れる**。数百〜数千 |
| GameJolt | 数百万〜1000 万 | itch と同じく自力次第 |
| Armor Games | 数百万(往年より縮小) | 審査を通れば安定した数 |
| ふりーむ！ | 数百万(日本) | 新着に載るので数百〜数千 |
| PLiCy | 数十万(日本) | 小さいが、置くだけなら損はない |
| Steam | 桁違い | **無名の小品は埋もれる** |

**大きいサイトほど、置いても届かない**という逆転が起きる。
Poki や CrazyGames は「選ばれたら大量に流れる」宝くじで、選ばれるために
スマホ対応・SDK 組み込み・品質審査という手間が要る。

対して **Newgrounds と ふりーむ！ は、新作が自動的に一度は人目に触れる仕組み**を持つ。
Newgrounds は投稿作を全員で判定する流れがあり、ふりーむ！ は新着一覧がある。
桁は小さいが、**置いただけで数百は動く**のはこの 2 つ。

**itch.io は流入源ではなく受け皿**と考えるのが正確。自然流入はほぼ期待できない。

## Steam に出す場合

技術的な壁はほぼないが、手間と費用がかかる。

| | Steam | itch.io |
|---|---|---|
| 登録料 | 1 タイトル 100 ドル | 無料 |
| 審査 | あり(数日〜) | なし |
| 必要なもの | 実行ファイル、税務情報、銀行口座、ストア素材一式 | zip とページの文章 |
| ブラウザで遊べるか | 不可 | **そのまま遊べる** |

- **Electron で包む**のが素直。中身は静的ファイルなので、そのまま入れて読ませるだけ。
  Tauri のほうが軽いが OS 側の WebView に依存するので、AudioWorklet まわりの挙動が
  環境で変わる。音が肝のゲームなので Chromium を同梱する Electron のほうが安全
- ランキングは、いまのサーバをそのまま使うか Steam のリーダーボードに載せ替えるかを選ぶ。
  後者は Steamworks の API を叩くので、それなりの作業になる

### 出す前に確認すること

- **SUNO で作った mp3 の商用利用**。プランによって扱いが変わる。
  MML の曲は元ネタのクラシックがいずれも著作権切れなので問題ない
- **AI 生成コンテンツの申告**。Steam は申請時に AI 要素の有無を申告させる。
  このゲームはコードも絵も曲も AI 製なので、当然申告する(隠すと問題になる)

## 独占について

**どこも独占を求めない。**itch.io に出しても Steam に出しても、同じものを
別の場所に置ける。権利はすべて作り手に残る。

独占が出てくるのは、**お金の絡む契約を結んだとき**だけ。CrazyGames や Poki には
独占掲載を条件にスポンサー料を払う仕組みがある。そういう話を受けるときだけ、
契約に独占条項が無いか読む。

Steam には「Steam のキーを他所で Steam より安く売ってはいけない」という決まりがあるが、
これはキーの話で、別バージョンを他所で配ることは妨げない。

## ランキングを分散させない

送り先は決め打ちなので、**どこに置いたコピーからでも同じ表に載る**
([online/ranking-remote.js](../online/ranking-remote.js))。

ただし配布先を増やすと、サーバ側に 2 か所の設定追加が要る。

- **CORS の許可**。ここで注意が要るのは、**itch はゲームを `itch.io` ではない
  別ドメインで動かす**こと。`*.itch.zone` のような配信専用のドメインになるので、
  `itch.io` を許可しても通らない
- **Turnstile のドメイン設定**。ウィジェットはドメインに紐付いているので、
  登録しないと本番への送信が弾かれる。しかも itch では iframe の中で動くので、
  素直に動くかは実際に試すまで分からない

### もうひとつの考えかた

`online/` フォルダを外したビルドを配る手もある。外すと**手元の記録だけ**になり、
サーバへは何も飛ばない([online/README.md](../online/README.md))。

共有ランキングは Cloudflare 版だけの機能にして、ほかに置くコピーは
「遊べるけれど記録は自分の中だけ」にする。サーバ側の設定を増やさずに済むうえ、
**なりすまして書き込まれる経路を 1 か所に保てる**。

### 切り替えは作らない

遊ぶ人が「手元だけ / 共有」を切り替えられるようにはしない。

理由は、**それが必要になる場面がもう塞がっている**から。サーバに送れなかったときは
すでに手元の保存に落ちて、画面にも「送れた / 手元だけ」が出る。
つまりオフラインやサーバ障害の動機は自動で処理されている。

そのうえで切り替えを出すと、見た目が同じ表が 2 つあることになり、
「さっきの記録が消えた」と受け取られる。どちらを使うかは**ビルドが決める**。
どうしても要るときは DEV SETTINGS の中に置く(公開版には出ない)。

## 保全

長く残すことを目的にするなら、置きかたで残りかたが変わる。

| 置き場所 | 性格 |
|---|---|
| Cloudflare Pages | いまの本体 |
| GitHub Pages | ソースと動くものが同じ場所にある。片方だけ失われない |
| Internet Archive | 保全そのものが目的の場所 |
| itch.io | 冗長化のついでに置ける |

**Wayback Machine に URL を投げるだけでは足りない。**クローラがたどれたファイルしか
保存しないが、このゲームは `online/ranking-remote.js` のように**実行時に動的に読む**
ものがある。URL が静的に書かれていないので抜け落ち、開いても動かないものが残る。

**zip をアイテムとして archive.org にアップロードする**ほうが確実。
`build-deploy.ps1` が作る zip がそのまま使える。Wayback にも投げておいて、
両方やっておくのがよい。

## いまの結論

Note と X はすでに動いているので、**外部サイトは「知らない人に見つけてもらう」ため
だけに置く**。その基準だと優先順位はこうなる。

1. **Newgrounds** と **ふりーむ！** — この 2 つだけが「置くと知らない人が来る」性質を持つ
2. **itch.io** — 急がない。保全の冗長化として置いておく程度
3. **Poki / CrazyGames** — スマホ対応が完全に済んで、審査に出す気力があるとき
4. **Steam** — 「ちゃんと売る」と決めてから

いずれもスマホ対応が済んでからのほうが評価は上がる。急ぐ理由がなければ、
置き場所を増やすのは v1 のタイミングでよい。
