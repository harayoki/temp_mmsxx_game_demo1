# スマホ対応の考察（バーチャルパッド）

別セッションで進める前提の**設計メモ**。まだ実装していない。
ここに書いてあるのは「決まったこと」と「まだ決めていないこと」で、
決まったことは変えずに作ってよい。

---

## 1. 前提

- このゲームは **80 年代シューティングのオマージュ**。**連射は必須の腕前**であり、
  自動連射に置き換えてはいけない。指で連射できる作りにする
- **横画面プレイ前提**。ゲーム画面は 256x192（4:3）なので、
  横画面では**左右に空きができる**。そこにパッドを置く
- **PC ではキーボードを残す**（作っている最中も今までどおり遊べること）。
  スマホでキーボードを受けるかは未定（6 節）
- パッドは**エンジンの任意部品**（`engine/util/` に置く）
- **ゲーム側（`game/main.js`）は PC 用のコードのまま動かす**。
  タッチとキーボードの差は**すべてエンジン側で吸収する**

## 2. 入力の流し込み ― **実装済み**

エンジンの `Input`（`engine/input.js`）に口を足した。`setVirtual(code, bool)` という
1 つの関数ではなく、**押す / 離す / 全部離す**の 3 つに分けてある（キーボードも同じ道を通る）。

```js
// 押した / 離した を、キーボードと同じ扱いで流し込む
mmsxx.input.press('ArrowLeft');
mmsxx.input.release('ArrowLeft');
mmsxx.input.clear();            // 画面が非アクティブになったときなど
```

- `down` / `pressed` の更新はキーボードと同じ規則
  （**押していない状態から押した瞬間だけ** `pressed` に入る）
- ゲーム側は `isDown()` / `wasPressed()` を読むだけなので、**変更不要**

### 行送りは「押した長さ」から出す ― **実装済み**

一覧を送るところは `repeat(code, delay, gap)` を読む。押した瞬間に 1 歩、
`delay`（既定 20 コマ）待ってから `gap`（既定 4 コマ）おきに 1 歩。

これで**指の動きと画面側の読みかたが噛み合う**。

| 指の動き | 流し込みかた | 画面側の結果 |
|---|---|---|
| タップ | 1 コマだけ押す | ちょうど 1 歩 |
| 長押し | 離すまで押しっぱなし | 初動待ちのあと連続 |
| フリック | 距離に応じて N コマ押しっぱなし | 勢いのぶんスクロール |

**呼ぶ側はどれが来たか知らずに済む。** 以前の `isDown() && frame % 4 === 0` は
押した瞬間に進む保証がなく、タップを取りこぼすことがあった。

### 端末の見分け ― **実装済み**

`engine/util/device.js` の `isMobileLike()`。`?device=mobile` / `?device=desktop` で
上書きできる。詳しくは [UTIL.md](UTIL.md) の 9 節。

- 出しかたを変えるためのもので、**キーの受け付けは塞がない**
  （タブレットに繋いだキーボードでも名前は打てる）
- **キーボードが付いていてもスマホはスマホ**として扱う

## 3. 十字キー：**位置が移動する相対型**

固定の十字ではなく、**触れたところが原点**になる方式。

| 決めごと | 内容 |
|---|---|
| 原点 | 左エリアに指が触れた場所。そこに十字の絵が現れる |
| 入力 | 原点からの**向き**で決める。8 方向のデジタル（斜めは 2 つ同時押し） |
| しきい値 | 原点から **一定距離（仮に 12px）以上**動いたら方向が立つ。それ未満は無入力 |
| 追従 | 指が離れるまで、原点は動かさない。ただし**大きく離れたら原点を引きずる**（仮に 48px を超えたら、その距離を保つように原点を移動）|
| 離したとき | 十字の絵を消し、方向をすべて離す |
| 8 方向の切り分け | 角度を 45 度ずつ 8 等分。境目で**ばたつかないよう、少しだけ重ねる**（ヒステリシス）|

**理由**: 避けながら撃つゲームなので、指の位置を見ずに操作できるほうが強い。
固定十字は「押している場所」を目で確かめる必要があり、弾を見る時間が減る。

## 4. ショットボタン：**こすり打ち**

**決まっていること**

- 連射は**腕前のまま**。押しっぱなしの自動連射にはしない
- 指を**こすると連射になる**。80 年代のパッドを爪でこする感覚に寄せる
- 移動しながら撃てること（**マルチタッチ必須**）
- **領域に入ったら PRESS、出たら RELEASE**。キーボードの押す / 離すとまったく同じ扱いにする。
  ゲーム側は `wasPressed('Space')` を見ているので、入るたびに 1 発になり、
  指を置いたままでは撃たれない

**やりかたは未定**。候補は次のとおりで、実機で触ってから決める。

| 案 | 中身 | 気になるところ |
|---|---|---|
| A. 領域を割る | ボタンを小さな区画に割り、**区画に入ったら PRESS・出たら RELEASE** | 区画の大きさで連射速度が決まってしまう |
| B. 動いた量で数える | ボタンの中で指が一定距離動くたびに PRESS / RELEASE を 1 往復 | 速さがそのまま連射に出る。しきい値の詰めが要る |
| C. 領域はひとつ | ボタン全体に**入ったら PRESS・出たら RELEASE**（いちばん素直） | こするというより「出入り」。ボタンを小さめにすれば成立する |

**どれにしても、連射の上限はゲーム側の `maxVolleys` で頭打ちになる**ので、
入力の作りで壊れることはない。

## 5. GUI は DOM

canvas の中には描かない。**canvas の外に HTML 要素**を置く。

| 決めごと | 内容 |
|---|---|
| 置き場所 | 横画面の**左右の空き**。左に十字、右にショット |
| 重なり | ゲーム画面の上には**重ねない**（指が弾を隠すため）|
| 見た目 | ドット絵風にする（角を丸めない、原色に近い色、`image-rendering: pixelated`）|
| 押した感じ | 触れているあいだ明るくする。**音は鳴らさない**（ゲームの音を邪魔しない）|
| 大きさ | 画面の短辺に対する割合で決める。設定で変えられるようにする |
| 左右入れ替え | 設定で用意（左利き向け）|

**理由**: ドットを汚さない、指の追従が滑らか、大きさや透明度を CSS で扱える。
canvas のボーダーに描く案は、60fps の描き直しと細かい表現の割に得がない。

## 6. キーボードとの併用

- **PC ではキーボードを残す**。パッドを作っている最中も、今までどおり遊べること
- **スマホでキーボード入力を受けるかは未定**。
  外付けキーボードを挿している人をどう扱うか、その場になってから決める
- パッドの**表示**は出し分ける
  - 一度でも画面に触れたら出す
  - `?pad=1` で強制的に出す（PC での確認用）
- どちらから来た入力かをゲーム側は区別しない

## 7. 画面の向きと大きさ：**強制的に横で見せる**（エンジン側は実装済み）

「横にしてください」とは出さない。**縦に持っていても、中身を 90 度回して横で見せる**。

**もうエンジンに入っているぶん**（`engine/video.js` の `_applyCssSize`）

| 決めごと | 内容 |
|---|---|
| canvas の中身 | **等倍**（264x200）。拡大はしない |
| 見た目の大きさ | CSS で決める。**実際の画素で整数倍**になる いちばん大きな値を選ぶ |
| 倍率の上限 | 起動時に渡した `scale`（既定 3）。大きな画面で無闇に拡大しない |
| 向き | **ゲームの長い辺を、画面の長い辺に合わせる**。食い違っていたら `rotate(90deg)` |
| 回すのはいつ | **`pointer: coarse` のとき（指で触る端末）だけ**。PC で窓を縦長にしても回さない |
| 取り直し | `resize` / `orientationchange` で。`resize` は途中の大きさでも飛んでくるので、次の描き替えまで待ってから測る |

整数倍にする理由は、中途半端な倍率だと **1 ドットが 2 画素だったり 3 画素だったりまだらになる**ため。
ぼけるのではなく、斜めの線がガタつき、文字の太さが場所によって変わる。

**まだ入れていないぶん**

- **タッチの座標も回す**。回した見た目の上で指を置いた場所と、
  当たり判定の場所がずれないようにする（`pointer` の x/y を同じ角度で変換する）
- 回っているかどうかは `mmsxx.vdp.rotated` で分かる

## 7-2. 全画面：**ホーム画面に追加してもらう**

- iPhone の Safari は `requestFullscreen()` に**対応していない**（iPad は対応）。
  API での全画面は望めない
- **ホーム画面に追加すれば全画面になる**。指定はこの 3 つ
  ```html
  <meta name="apple-mobile-web-app-capable" content="yes">
  <meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">
  <meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
  ```
  あわせて `manifest.json` に `"display": "standalone"`（Android は `"fullscreen"`）。
  iOS は古い `apple-*` の指定も見るので、両方書いておく
- アドレスバーが消えるぶん**縦が広く取れる**ので、整数倍が 1 段階上がることがある
- 横スワイプの「戻る」が無効になる（ゲームには都合がよい）
- 下端のホームバーはスワイプを吸うので、`env(safe-area-inset-bottom)` を空けてパッドを置く
- **全画面にしても向きは固定できない**（`screen.orientation.lock()` は iOS 未対応）。
  上の 90 度回転は、全画面にしても要る

## 8. 取りこぼし・ブラウザ対策

### 指の取りこぼし

- `pointerdown` / `pointermove` / `pointerup` / **`pointercancel`** をすべて拾う
  （着信やジェスチャで指が消えることがある）
- **`pointerId` ごと**に「左の十字か、右のボタンか」を覚える。
  途中で担当を入れ替えない
- 指がボタンから滑り出ても、**離すまでは同じ担当のまま**。
  `setPointerCapture()` で捕まえておくと続きが届く。
  **失敗しても先へ進むこと**（例外で `pointerdown` の残りが飛ぶ）
- 音は最初のタッチで解禁する（いまのキーボードと同じ扱い）

### iOS で指の動きにページを持っていかれないための決めごと

実機（iPhone / Safari）で確かめた。**4 つそろって初めて効く。**

**1. ページ自体をスクロールできなくする**（いちばん効く）

```css
html, body { position: fixed; width: 100%; height: 100%; overflow: hidden; }
```

バウンススクロールは `overscroll-behavior` では**止まらない**。ページを固定するのが確実。

**2. `touch-action: none`**

body と、指を受ける要素に当てる。「この指はスクロールや拡大に使わない」と
**先に**ブラウザへ伝える指定。これが無いと**ブラウザが先に指を持っていき**、
一度スクロールと判断されたら、あとから `preventDefault()` しても戻せない。

**中身を送る欄がある場合は向きに注意。** `pan-y` は「画面の上での縦」なので、
90 度回して見せているときは `pan-x` に入れ替える（さもないと送れなくなる）。

**3. `touchmove` の `preventDefault()` は `{ passive: false }` を明示する**

```js
document.addEventListener('touchmove', (e) => e.preventDefault(), { passive: false });
```

**iOS 11.3 以降、`touchmove` は既定で passive 扱い。**
`{ passive: false }` が無いと `preventDefault()` は**黙って無視される**。
「書いたのに効かない」はたいていこれ。

**4. `pointerdown` で `preventDefault()`**

### 拡大・長押しメニュー

| 何を止めるか | やりかた |
|---|---|
| つまむ拡大 | `gesturestart` / `gesturechange` / `gestureend` を `preventDefault()` |
| **ダブルタップの拡大** | 上では止まらない。**2 回目のタップの `touchend` を潰す**（350ms 以内）。ボタンや入力欄の上では潰さないこと（クリックが飛ばなくなる）|
| 長押しメニュー（コピーなど） | `-webkit-touch-callout: none` と `-webkit-user-select: none`。**Safari は接頭辞つきでないと効かない。** 中の文言まで届くよう子孫にも当てる。あわせて `contextmenu` も `preventDefault()` |
| 3 本指タップ | **止められない。** OS の「ズーム」（設定 → アクセシビリティ）が先に取る。3 本指のジェスチャを使うなら、誤動作する前提で組む |

`user-scalable=no` と `maximum-scale=1` は **iOS が無視する**。書いても害は無いので、
ほかのブラウザのために入れておく程度。

### 下端のホームバー ― **実機で確かめた**（2026-08-09）

**ホームバーの帯は本当に反応する。** そこへパッドやボタンを置くと、指がバーに
取られて操作が抜ける。「たぶん吸われる」ではなく、実機で起きることを確認した。

- 横持ちだと**下の長い辺に沿って**居る。厚みは 21px ほど
- **ノッチがどちら側にあっても、ホームバーはいつも居る**。左右のくびれとは別の話
- `env(safe-area-inset-bottom)` を読んで、その帯には
  **十字の当たり判定もボタンも伸ばさない**（`engine/util/touchgui.js`）
- 読むには `viewport-fit=cover` が要る。書いていないと `env()` は 0 を返す

### Android の「戻る」― **env() には出てこない**

ノッチもホームバーも Android に同じものがあり（ディスプレイカットアウト /
ジェスチャーナビ）、**どちらも `env(safe-area-inset-*)` で同じように読める**。
Chrome for Android も `viewport-fit=cover` で返す。

問題は**そこに出てこないもの**のほう。

- Android のジェスチャーナビは、**左右どちらの端から内へ払っても「戻る」**になる
- 横持ちだと、その端は**十字とショットを置いている場所そのもの**
- ネイティブなら `setSystemGestureExclusionRects` で除外できるが、
  **web ページからは切れない**。OS が先に取る
- `env()` には出てこないので、避けるにはこちらで帯を空けるしかない

**画面の左右の端 20px は指を受けない**ことにした（`TouchGui` の `edgeGuard`）。
**機種は見ない。** iPhone に入れても害が無く、見分けを間違えるほうが危ない。
十字は「触れたところが原点」なので、端に置けなくなるだけで操作性はほとんど落ちない。

空けるのは**回す前の画面の左右**。OS のジェスチャは見た目の向きではなく、
実際の画面の端に張り付いているため。

## 8-2. スマホ向け GUI を **エンジンの部品にしたい**（まだ早い）

いま `engine/util/touchgui.js` にある器は、**部品の置き場所には居るが、まだ部品ではない**。
STAR FABLE のことを知りすぎている。**汎用化はもう一段あと**にする。

**もう汎用な部分**（そのまま持っていける）

| | |
|---|---|
| `planSideLayout()` | 左右の空きの割りかたを決めるだけの関数。DOM も端末も見ない。数字を入れれば同じ答えが返るので試験にも掛かる |
| `TouchControls`（`touch.js`） | 十字とショット。入れ物を渡せば中身を作るだけ |
| `createGesture()`（`gesture.js`） | ジェスチャの見分け。キーのことを知らない |
| `DEVICES`（`devices.js`） | 確かめたい機種の寸法 |

**まだゲームに寄っているところ**

- **ゲーム画面が「器の真ん中にある」前提**。横画面・1 枚の canvas を決め打ちしている
- **モードが `game` / `menu` の 2 つ固定**。3 つ目（たとえば地図やインベントリ）を足す口が無い
- **キーコードへ変換する形が前提**。V2 でポインタを扱うなら、この層ごと入れ替わる
  （[UTIL.md](UTIL.md) / `v2-pointer-input`）
- **ボタンの並びと役割**（ミュート / 拡大縮小 / ピクセルパーフェクト / カメラ）が
  このゲームの都合。部品にするなら「借りる側が並べるもの」にしないといけない
- **`--r` の 0.3 倍下げる**のような、実機で詰めた数字が式に直接入っている

**部品にするときの筋**

1. 器は「**左右の帯を作って貸すだけ**」にする。中身（パッド・ボタン・案内）は借りる側が入れる
2. モードは名前の付いた集合にして、**モードごとに何を出すかを渡してもらう**
3. 実機で詰めた数字は、式から出して**つまみ**へ集める

**急がない。** V2 でポインタ入力を入れるときに、どのみち作り直すことになる。
それまでは STAR FABLE で使い倒して、**動かなかった決めごとを見つけるほうが先**。

## 8-3. **いまの実装**（2026-08-11 現在）

ここから下の 9〜12 節は**作りはじめる前の計画**で、いまの姿とは違うところがある。
**動いているものはこの節が正**。

### ファイルの役割

| ファイル | 受け持ち |
|---|---|
| `engine/util/touch.js` | 十字とこすり打ち。**DOM も当たり判定もここ**。ゲームを知らない |
| `engine/util/gesture.js` | 払う・つまむの見分けだけ。**触らない**（別セッション製） |
| `engine/util/touchgui.js` | 上の 2 つをゲームへ繋ぐ器。左右の空きの割りかた・案内・ボタン |
| `engine/input.js` | 倒した向きと強さの口（`setStick` / `stick`） |
| `game/main.js` の末尾 | **どの画面で何ができるか**の表（`menuGuide` / `TG` / `OK` / `OPTBTN`） |

### 向きと強さは 1 つの口から

矢印キーは 4 方向しか無いので、**指の速さもパッドの倒し量もそこで消えていた**。
機器は生の向きと強さを置き、**いくつの方向へ丸めるかは読む側が決める**。

```js
input.setStick(source, x, y)   // 機器が置く（1 を超えてよい）
input.stick(8)                 // { angle, rad, strength, sector, source }
```

- キーボード … 押している矢印から 8 方向。強さ 1
- タッチの十字 … 下の `stickMode` しだい
- パッド … 軸の角度と倒し量

**倒し量のあるほうが勝つ。** タッチもパッドも倒しながら矢印キーを出している
（メニューがそちらで動いている）ので、キーを先に見ると自分の倒し量が自分で消える。

自機の移動は `game/main.js` の `MOVE_SNAP`（既定 0 = 丸めない）/ `MOVE_ANALOG`
（既定 入り）/ `MOVE_GAIN`（既定 1）。**軸ごとに足すのはやめた**ので、
斜めが √2 倍 速いことは無くなっている。

### 十字は 2 通り（`stickMode`）

| | 中身 |
|---|---|
| `'origin'`（既定） | 触れたところが原点。倒した向きを保てる。**折り返しは原点をまたぐまで効かない** |
| `'move'` | いま指が動いている向き。折り返しがその場でつながり、**指を止めれば止まる** |

つまみは `deadzone` / `dragMax` / `stickFullDist`（origin）と
`stickMinSpeed` / `stickFullSpeed` / `stickMaxPower`（move）。
**実機で詰めるのは `tools/touch-tool/`**。決めた値をそのまま貼れる形で出る。

ポーズ中に **PAD RESPONSE**（LOW / NORMAL / HIGH）で段を選べる。
変えているのは「全速に届くまでの指の速さ」だけで、**自機の最高速は動かさない**
（上げるとキーボード（常に 1）より指が速くなり、記録の公平さに触る）。

### 撃ちかたは裏返っている（`idleFire`）

| 指 | SPACE |
|---|---|
| 触っていない | **押しっぱなし**（ゲーム側のゆっくりの自動連射。13 コマ間隔） |
| 置いて動かさない | 離す（**止めるために触る**） |
| こする | そのぶん押し直す（往復ごとに 1 発） |

**メニューでは必ず離す**（押しっぱなしのままだと選ぶ操作が壊れる）。
受け取る側が入力を捨てても戻るよう、遊びの最中は `keepFire()` を毎コマ呼ぶ。

### 指を受ける場所

- **十字** … 左の帯 ＋ そこから右の端まで（連射の四角を除く全部）
- **連射** … **丸のまわり 16px の四角だけ**（`shotHitPad`）

指がずれるのは十字だけなので、広さが要るのもそちらだけ。
**`?areas=1` で色分けして見える**（青＝十字 / 赤＝連射）。

絵のほうは左右の帯に置き、**ゲーム画面へ 25% かぶせる**（`padBleed`）。
帯の幅は左右そろえる（片方だけ広いと絵の置き場所が食い違って見える）。

### 画面の向き

engine/video.js が `viewAngle`（0 / 90 / 180 / 270）を 1 つだけ持ち、
**器も点の逆変換も指の動きもそれを見る**（`viewTransform` / `viewToLocal` /
`turnDelta` / `turnInsets`）。**回すところが 4 つあるので、直すときは 4 つまとめて**。
180 度はポーズ中とタイトルのボタン、または `?turn=180`。

## 10. 差し替えできる形

ランキングと同じ考えかたで、**口を決めてから中身を作る**。

```js
const pad = new VirtualPad(mmsxx, {
  side: 'left',        // 十字をどちら側に置くか
  scale: 1,            // 大きさ
  onVisible: null,     // 出た / 消えたときの知らせ
});
pad.attach(document.body);   // DOM に取り付ける
pad.detach();                // 外す
pad.visible = true;          // 出し入れ
```

- 中身（DOM の作り・当たり判定）を差し替えても、**この口は変えない**
- ゲーム側は `pad` を触らない。触るのは起動のところだけ
