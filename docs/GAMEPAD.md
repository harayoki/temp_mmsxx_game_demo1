# ゲームパッド対応

**実装ずみ**。PC でもスマホでも、パッドを繋げばそのまま遊べる。
ここに書いてあるのは「何をどう作ったか」と「なぜそうしたか」で、
迷ったときはこの決まりに戻ること。

触るファイルは 4 つ。

| ファイル | 役目 |
|---|---|
| `engine/util/gamepad.js` | パッドを読んで、押した / 離した を呼び出し側へ通知する部品 |
| `engine/util/notice.js` | キャンバスの上に重ねる知らせ（読ませてゲームを止める） |
| `game/main.js` | このゲームでの割り当て・文言・SE |
| `tools/gamepad-tool/index.html` | 部品を単体で確かめる器（配布には入らない） |

---

## 1. 考えかた

**パッドの状態をキーのコードへ変換して、`Input` へ流し込むだけ**にした。
`press('ArrowLeft')` や `press('Space')` が通れば、
**ゲーム側の遊びのコードはキーボードのときのまま動く**。

これは `docs/SMARTPHONE.md` の 2 節（バーチャルパッド）と同じ考えかたで、
入口が増えても遊びのコードは 1 つで済む。

```js
const gamepad = createGamepad({
  // **第 2 引数の 'pad' を忘れない**。省くとキーボードで遊んだことになり、
  // ランキングへ誤った操作方法が載る(engine/input.js の usedInputs)
  press: (code) => mmsxx.input.press(code, 'pad'),
  release: (code) => mmsxx.input.release(code),
  map: PAD_MAP,
});
```

`gamepad.poll()` は **`mmsxx.run()` の先頭**で毎コマ呼ぶ。
エンジンは `update()` のあとに `input.endFrame()` を呼ぶので、
**押したそのコマで効く**（遅れ 0 コマ）。

## 2. Gamepad API の癖

作る前に知っておくこと。ここを外すと「動かない」の原因が分からなくなる。

- **イベントでは来ない**。毎コマ `navigator.getGamepads()` を読みに行く
- **ボタンを 1 回押すまで、そのパッドは見えない**。挿しただけでは一覧に出ず、
  `gamepadconnected` も飛んでこない（指紋取りの防止）。
  ページを読み込み直すと、また押すまで見えなくなる。
  **「繋いだだけで案内を出す」はできない**
- **https か localhost でないと動かない**
- 並びが決まっているのは `mapping === 'standard'` のときだけ

## 3. standard 以外は相手にしない

`standard` でないパッド（古い DirectInput のものなど）は、
**ボタンの番号が製品ごとにばらばら**で、十字が 1 本の軸に詰め込まれていることもある。
当てずっぽうで読むと、**押していないボタンでポーズが掛かる**ような目に遭う。

なので `usable()` で `standard` だけを相手にし、それ以外は `unsupported()` として
「対応していない形式です」と伝えるだけにした。ここ 10 年のパッド
（XInput 全般、DualSense、Switch Pro など）はほぼ `standard` なので、表 1 つで足りる。

キーコンフィグは**作らない**。割り当てはゲームごとに違うので、部品には持たせない。

## 4. 割り当て（このゲームの場合）

`game/main.js` の `PAD_MAP` 1 つで決まる。差し替えるときはこの表だけを直す。

| パッド | キー | 効き |
|---|---|---|
| 十字 12〜15 / 左スティック | 矢印 | 移動・メニュー |
| A(0) / B(1) | `Space` | ショット・決定 |
| X(2) / Y(3) | `Escape` | 戻る・ポーズ |
| START(9) | `Escape` | ポーズ |
| それ以外のボタン | `Space` | ショット |

**余ったボタンも全部ショット**にしてある。押し間違いが起きないゲームなので、
遊ぶ人がどのボタンに親指を置いても弾が出るほうがよい。覚えることも増えない。

- 十字とスティックは**どちらでも動く**（OR で合成）
- スティックの遊びは **0.5**。実機（XInput）は据わりが ±0.000、倒しきりが ±1.000 で、
  この値なら窮屈でもなく、揺れも拾わない
- **連射は入れない**。こすり打ちのゲームなので、こちらから連射を足すと記録の意味が変わる。
  なお**パッド側が持っている連射は止められない**（人が速く叩いたのと同じ形で届く。
  間隔の揃いかたで推測はできるが、誤判定が出るので弾かない）

## 5. 使うかどうかを聞く

パッドが押されたら、**キャンバスの上に白い札を出してゲームを止める**。

```
ゲームパッドを認識しました。
[ 使う（SPACE） ] [ 使わない（ESC） ]
```

- **タイトル（ランキングの一覧もここ）のときだけ出す。**
  遊んでいる最中に出すと弾の合間でも画面が凍るし、リプレイの再生ともかみ合わない
  （絵はエンジン側で進み、ゲームだけ止まる）。
  途中で繋いだ人は、次にタイトルへ戻ってボタンを押したときに気づく
- **答えるまでパッドの入力は流さない。** 断ったあとも流さない
- **断られても、また押されたらもう一度聞く。**
  ただし **ESC が 3 回続いたら、そのページでは黙る**
  （ボタンの張り付きなど、こちらの都合ではない何かが起きている）
- 対応していないパッドは、番号が読めないので「また押されたら」ができない。
  **1 ページに 1 回だけ**知らせる
- 文言は日本語環境なら日本語、それ以外は英語（`pickLanguage(['ja'], 'en')`）

### なぜキーかクリックを求めるのか

**ブラウザはパッドの操作を「人が触った」と数えない。**
キーかクリックが 1 回ないと音が鳴りはじめないので、
この札に答えてもらうこと自体が**音の解禁を兼ねている**。

キーボードの無い端末は**ボタンでしか答えられない**ので、
`engine/util/notice.js` はボタンを押したときに `audio.unlock()` を呼ぶ。

### 札を消したキーはゲームへ渡さない

エンジンの `keydown` が先に走って、押されたことがもう控えられている。
そのままだと、タイトルでスペースを押しただけでゲームが始まってしまう。
`notice.hide()` で `input.clear()` と `input.pressed.clear()` を呼んでいる。

## 6. 名前入力

パッドには `Enter` が無いので、**5 桁の右に決定の 1 文字を足した**
（フォントの `0x1C`＝改行マーク）。桁と同じように左右で選べて、
そこでショット（`Space`）を押すと確定する。5 文字打ち終わると自然にそこへ移る。

`Escape`（＝X / Y / START）は今までどおり「書かずに飛ばす」。

## 7. ランキング

`press(code, 'pad')` の第 2 引数で、`engine/input.js` が使われた操作方法を控える。
`usedInputs()` が `key+pad` のような形で返し、`game/main.js` の `rankInput()` が送る
（`docs/TODO.md` の O 章）。**第 2 引数を省くとキーボード扱いになり、黙って誤った値が残る。**

## 8. 確かめかた

`tools/gamepad-tool/` をブラウザで開く。ゲームには依存しないので、
`engine/util/gamepad.js` を持っているどのゲームからでも使える。

- つながっているパッドの一覧（`id` / `mapping` / ボタンと軸の本数）
- 全ボタンの押下状態と、全軸の生の値（数字と棒グラフ。遊びの境目を重ねて出す）
- 部品が出した通知（コマ番号・遅れ・標本の古さ）
- つまみ（遊び・十字と軸のどちらを見るか・連射・使うパッド・振動を試す）

パッドが手元に無くても、`navigator.getGamepads()` を差し替えれば偽のパッドで試せる。

## 9. まだやっていないこと

- **振動**（`gamepad.vibrationActuator`）。確認ツールで試せるだけで、ゲームには入れていない
- **`standard` でないパッドへの対応**。方針として作らない
