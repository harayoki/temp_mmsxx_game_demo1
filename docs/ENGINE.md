# MMS-XX Engine ドキュメント

MSX1(TMS9918)風の見た目と音を再現するブラウザ用ゲームエンジンです。
GUI ツールは無く、**ゲームデータをコードで書く**スタイルで作ります。

## 名前について

**MMS-XX** は **Mock Machine System, model XX** の略。
実在しなかった機械の、実在しなかった試作機という意味です。
`XX` は型番なので、この先の世代は型番のほうを変えていきます。

コードの中の識別子(`MMSXXEngine` / `mmsxx`)はハイフン無しのままです。
**表に出す綴りは `MMS-XX`** に揃えてください。

## 画面のしくみ

- 表示画面は既定 **256x192**。**8 ドット単位で増減**できます(`setScreenSize`)
- その外に**ボーダー**を置けます(`setBorder`)。何も描かれず、いつも背景色です
- **画面全体を 1 ドット単位でずらせます**(`setAdjust`。実機の SET ADJUST 相当)。
  ずらしたぶん反対側から回り込むことはなく、空いたところは背景色になります。
  画面をぶるっと揺らす演出に使えます
- 裏画面(仮想画面)は **256〜2048 の 2 の冪**で指定します
- 裏画面はレイヤーごとに別の大きさを持てます。**枚数に上限はありません**
- 各レイヤーは独立したスクロール位置を持ち、上下左右にリピート(ラップ)します

```js
import { MMSXXEngine } from './engine/engine.js';

const mmsxx = new MMSXXEngine(canvas, {
  scale: 3,
  virtualWidth: 256, virtualHeight: 1024,   // 既定サイズ
  layers: [{}, {}, {}, {}, {}],             // 5 枚。{width,height} で個別指定も可
});
```

描画の重なりは奥から
**背景色 → レイヤーと BG スプライト → 通常スプライト** の順です。

**レイヤーと BG スプライトは同じ優先度空間**を使います。
BG スプライトの `priority = n` は「**レイヤー n の手前**」という意味で、
レイヤーの合間に差し込めます(`n` が負なら全部のレイヤーより奥)。
たとえば「星より手前、大きな背景オブジェクトより奥」に置きたい流れ星は
`priority = 2` にします。

## 色の制約

RGBA 画像を書き込むと、自動で MSX1 の制約へ変換されます(結果はキャッシュされます)。

- MSX1 の 15 色パレットへ量子化(パレット 0 は透明)
- SCREEN2 と同じ **「横 8 ドットにつき 2 色まで」**
- **`bgSymbol()` で作るときにキャラパターンとして焼き込みます。**
  8 の倍数まで広げたうえで、**8x8 セル内に色 2 以上のパターンがあるセルの透明(0)は黒(1)**
  になります(「キャラパターンのあるセルは不透明」という実機 BG の見え方)。
  `{ backdrop: 12 }` のように埋め色を変えられます。**調べるときに色を変えると、
  どのセルがどの絵のものか画面で分かります**
- 絵はセル単位で完成しているので、**描くときには何も均しません**。
  **重なったセルは、あとから描いた絵のものに丸ごと入れ替わります**
  (実機でキャラクタを書き換えるのと同じ)。1 つのセルを 2 つの絵が分け合うことはないので、
  **どちらを上にするかは呼ぶ側が描く順で決めます**
- BG スプライトも同じ絵を使うので、同じ規則です
- スプライト用に「画像全体で N 色まで」の変換モードがあります
  - `{ colors: 1 }` = 実機の単色スプライト
  - `{ colors: 2 }` = スプライト 2 枚重ね風
  - こちらは透明をそのまま保つので、穴あきスプライトが作れます

8 ドットの境界は「画像自身の x=0 起点」です。レイヤーに描くときに x を 8 の倍数へ
置くと、実機の SCREEN2 と同じ見え方になります。

### 絵の大きさの決まり

| 種類 | 決まり | 破るとどうなるか |
|---|---|---|
| BG スプライト | **8 の倍数(必須)** | 端のセルが半分しか黒で埋まらず、そこだけ下の色と混ざる |
| 通常スプライト | **16 の倍数を推奨**。16x16 に収まるものは自由 | 見た目だけの話(実機のスプライトが 16x16 単位) |
| BG パーツ(レイヤーへ描く絵) | 自由 | **右と下が 8 の倍数まで黒で埋まる**。規則は保たれる |

BG パーツで 20x12 の絵を渡すと、24x16 の黒い升目に収まって見えます。
**広げるのは `bgSymbol()` の中なので、`width` / `height` も 24x16 になります。**
気にしないならそのままで構いません。ぴったり出したいときだけ 8 の倍数で作ります。

### 素材の検査(エンジン側)

BG スプライトを作ったとき・レイヤーへ描く絵を変換したとき・スプライトを作ったときに、
**その絵につき 1 度だけ**検査が走ります。毎フレーム描いても手数は増えません。

```js
mmsxx.bgCheck = 'throw';  // 開発版の既定: 例外で止める(取りこぼさない)
mmsxx.bgCheck = 'warn';   // 公開版の既定: console に出して、そのまま動かす
mmsxx.bgCheck = 'off';    // 調べない

mmsxx.bgSprite(img, { bgCheck: 'off' });          // この絵だけ見逃す
layer.draw(x, y, img, true, { bgCheck: 'off' });

mmsxx.bgWarnings      // 見つかった違反の記録
mmsxx.checkLayer(0)   // レイヤー全部(裏画面ぜんぶ)。重いので手で呼ぶときだけ
```

引っかかった絵の**名前**がメッセージに出ます(`mmsxx.convert(raw, { name })` で渡した名前。
色替えや向き替えをした絵は `もとの名前(色替え)` のように出ます)。

**直すのは素材側の仕事**で、エンジンは絵に手を入れません。

### 減色(手で呼ぶ)

素材の時点で色数をそろえるのが本筋ですが、やむを得ないときのために
**明示的に呼ぶ減色**を用意してあります。**エンジンが自動で呼ぶことはありません。**

```js
mmsxx.vdp.reduceForSprite(rgba, 2);   // 多い順に 2 色残して、近い色へ寄せる
mmsxx.vdp.reduceForBG(rgba);          // SCREEN2 と同じ見え方に落とす
```

`reduceForBG` は 3 段でやります。

1. **15 色 + 中間色**(2 色のディザで作れる色)の中でいちばん近い色を選ぶ
2. **横 8 ドットに 3 色以上**あれば、多い順に 2 色を残して近いほうへ寄せる
3. **8x8 のセル**を見て、絵のあるセルの透明を背景色(既定は黒)で埋める

**TODO(v2)**: 外から絵を取り込む口を作るときに、ここを作り直します。
中間色を**ディザとして 2 色へ振り分ける**、**8x1 のグリッドで見るモード**を足す
(8x8 のセル塗りをしない)、誤差拡散を選べるようにする、の 3 つです。
自動で均すのは `assets-src/makedata.mjs` の `BG_IMAGES` に入れた絵だけです。

## API

```js
// ---- 画面 ----
mmsxx.backdrop = 4;                    // 背景色 (パレット番号 1..15)
mmsxx.screenWidth; mmsxx.screenHeight;   // 描画領域(既定 256x192)
mmsxx.setScreenSize(240, 176);         // 8 ドット単位で増減できる
mmsxx.setBorder(16, 8);                // ボーダー(描画領域の外の遊び)の厚み
mmsxx.outWidth; mmsxx.outHeight;         // ボーダー込みで実際に出ている大きさ
mmsxx.setAdjust(-2, 1);                // 画面全体を 1 ドットずらす(-15..+16)
                                     // 回り込まず、空いたところは背景色になる
// ---- 画面のキャプチャ ----
// 実描画そのものが原寸のオフスクリーンなので、原寸の取り出しがいちばん安い
mmsxx.capture();                       // data URL (image/png)
mmsxx.capture({ type: 'blob' });       // Promise<Blob>
mmsxx.capture({ type: 'canvas' });     // canvas(複製)
mmsxx.download('shot.png');            // そのまま保存
mmsxx.layerCount;                      // レイヤー枚数
mmsxx.isLocal;                         // 手元の開発中か(localhost / file:)
                                     // デバッグ機能の出し分けに使う

// ---- エラーログ ----
// 日付ごとに 1 つ、3 日ぶんだけ残す(起動時に古いものを消す)。
// 手元の開発中はエラーでそのまま止め、公開版は致命的でなければ続ける。
mmsxx.errors.log('なにか変');           // 自分で 1 件記録する
mmsxx.errors.log('致命的', { fatal: true });
mmsxx.errors.read();                   // 今日のログを読む
mmsxx.errors.days();                   // 残っている日付(新しい順)
mmsxx.errors.clear();                  // 全部消す
mmsxx.virtualWidth; mmsxx.virtualHeight; // 既定の裏画面サイズ

const bg = mmsxx.layer(0);             // レイヤー取得 (0 が奥)
bg.draw(x, y, rgbaImage);            // RGBA画像を裏画面へ描画(自動MSX変換)
bg.draw(x, y, img, true, { flipX: true });   // 反転して描く
bg.draw(x, y, img, true, { rotate: 180 });   // 180度回転(90/270は非対応)
bg.fill(color, x, y, w, h);          // 塗りつぶし (color 0 = 透明クリア)
                                     // 位置と大きさは 8 ドット単位に丸められる
bg.fill(color, x, y, w, h, true);    // 第6引数 true で 1 ドット単位のまま塗る
                                     // (1 ドットずつ細くなる帯などに使う)
bg.setRepeat(false);                 // 画面の端で裏画面を繰り返さない
                                     // (既定は繰り返す。星空などはそのままでよい)
bg.setRepeat(false, true);           // 横だけ繰り返さない / 縦は繰り返す
bg.clear();                          // 全面透明クリア
bg.print(x, y, 'HELLO', 15);         // 内蔵フォント(1文字8x8)で文字描画
                                     // 英数字・記号のほかに **カタカナ**も持っている
                                     // (濁点は実機と同じく「カ」+「゛」の 2 文字)
                                     // 括弧 ( ) も入っている
                                     // **文字のます目(8x8)は既定で黒く塗る**ので、
                                     // 下にあった絵や文字は透けない
bg.print(x, y, 'HELLO', 15, 0);      // 第5引数 0 で塗らずに重ね書き
bg.print(x, y, 'HELLO', 15, 4);      // 好きな色で塗ることもできる
bg.scroll(x, y);                     // スクロール位置設定(ラップする)
bg.scrollBy(dx, dy);                 // 相対スクロール
bg.snap = 8;                         // 表示スクロールを8ドット単位に量子化(0=滑らか)
bg.visible = false;                  // レイヤー表示ON/OFF
bg.width; bg.height;                 // このレイヤーの裏画面サイズ

// ---- スプライト ----
const sp = mmsxx.sprite(rgbaImage);           // 生成 (個数制限なし)
const sp1 = mmsxx.sprite(img, { colors: 1 }); // 単色スプライト(実機風)
const sp2 = mmsxx.sprite(img, { colors: 2 }); // 2色(スプライト2枚重ね風)
sp.x = 100; sp.y = 50;               // 画面座標 (256x192)
sp.priority = 10;                    // 大きいほど手前
sp.visible = false;
sp.image = otherImage;               // 差し替え(アニメ用)
sp.flipX = true;                     // 左右反転
sp.flipY = true;                     // 上下反転
sp.rotate = 90;                      // 0 / 90 / 180 / 270 (時計回り)
sp.blink = 2;                        // 2フレームに1回だけ出す(実機風のちらつき)
sp.blinkOn = 2; sp.blink = 4;        // 2コマ出て2コマ消える(2:2)。既定は blinkOn=1
// ちらつきの位相は既定で「エンジンが自動でずらす」。同じ blink のものが
// いっせいに消えず、少ない枚数を回しているように見える。
sp.blinkPhase = 0;                   // 数字を入れると明示指定(0 でそろえれば同時に消える)
sp.blinkPhase = null;                // 自動に戻す
// パラパラアニメ(通常スプライト・BGスプライトの両方で使える)
sp.frames = [img0, img1, img2];      // image のかわりに順番に表示する
sp.frameRate = 6;                    // 6フレームごとに次のコマ
sp.framePhase = 0;                   // 同じ絵でもコマをずらせる
sp.frameLoop = false;                // 最後のコマで止める(1回だけのアニメ)
// 色の入れ替え(同じ絵から色違いを作る。絵を何枚も定義しなくてよい)
sp.colorMap = { 2: 7, 3: 5, 12: 4 }; // { 元の色: 新しい色 } パレット番号で指定
sp.colorMap = null;                  // 入れ替えなしに戻す
mmsxx.removeSprite(sp);

// ---- BG スプライト ----
// 通常スプライトより奥。位置は 8 ドット単位に丸められ、
// 大きさと枚数に制限はない(大きな敵や小惑星向け)。
// priority はレイヤーと同じ空間。n = 「レイヤー n の手前」。
const big = mmsxx.bgSprite(rgbaImage);
big.priority = 3;                    // レイヤー3の手前・レイヤー4の奥
big.x = 64; big.y = -32;
big.flipX = true;                    // 反転と 180 度回転のみ有効
mmsxx.removeBgSprite(big);

// ---- 画像 ----
// rgbaImage は {data: Uint8Array(RGBA), width, height} か ImageData。
// **絵はここで型を決めて作る**。決まりを守っているかの検査もここだけで走り、
// できたものは sprite() / draw() にそのまま渡せる(向こう側では調べない)。
const SHIP = mmsxx.spriteSymbol(rgbaImage, { name: 'SHIP', colors: 2 }); // スプライト用
const WALL = mmsxx.bgSymbol(rgbaImage, { name: 'WALL' });                // BG 用
// **入れものも用途ごとに分ける**と、取り違えに気づきやすい
// (STAR FABLE は SPRITE_SYMBOLS / BG_SYMBOLS の 2 つに分けている)
// 色番号で組み立てた絵(HUD の部品など)も、同じ口から型にできる
const TILE = mmsxx.bgSymbol({ width: 8, height: 8, pixels }, { name: 'TILE' });
MMSXXEngine.imageFromBase64(b64, w, h);          // gamedata.js の画像を復元

// ---- 走査線と色の置き換え ----
// 絵を 1 ライン おきに間引く「走査線」は、BG スプライトにも BG パーツにも付けられる。
// null = 入れない / 0 = 奇数行を抜く / 1 = 偶数行を抜く。
// 毎コマ 0 と 1 を入れ替えると、抜ける行が交互に動く。
sprite.scanline = (mmsxx.frame >> 1) & 1;                // スプライト
layer.draw(x, y, img, true, { scanline: 0 });          // BG パーツ
layer.scanline = (mmsxx.frame >> 1) & 1;                 // レイヤーまるごと
// STAR FABLE のエンディングでは 3 コマで 1 まわり(1:1:1)にしている。
//   位相 0 -> 位相 1 -> レイヤーごと消す
// 消す 1 コマをはさむと、位相の入れ替わりだけのときより落ち着いて見える。
// 抜いた絵は絵ごとにキャッシュされる(毎フレーム間引き直さない)ので、
// 非力な端末でも描く手数は元の絵と変わらない。
// 色番号の置き換えも同じように使える。1 枚の絵を色ちがいで描き分けられる。
layer.draw(x, y, img, true, { colorMap: { 2: 7, 3: 5 } });
// 1 ライン おきのディザ + 走査線の位相ずらし で、15 色にない中間色を目で作れる。

// ---- サウンド ----
mmsxx.audio.defineBGM('main', [mml1, mml2, mml3]); // トラックごとの MML 配列
mmsxx.audio.defineSE('shot', mml);
mmsxx.audio.playBGM('main', true);     // 第2引数 = ループ
mmsxx.audio.fadeOutBGM(1.5);           // 秒数をかけて消す
mmsxx.audio.playJingle('fanfare');     // ジングル(ファンファーレなど)。
                                       // **BGM は止めず、鳴っているあいだだけ黙る**ので、
                                       // 終わると曲の続きが聞こえる(頭出しし直さない)
mmsxx.audio.jingling;                  // ジングルが鳴っているか
mmsxx.audio.stopBGM();
// SE は「空いている音があればそこで鳴る」。ショットと爆発が同時に鳴ることもある。
// 同時に鳴らせる音の数は new MMSXXEngine(canvas, { maxVoices: 8 }) で決める
// (エンジン側に上限は無い。BGM が使っているぶんも数に入る)。
// 空きが足りないときは、優先度の低い SE を止めて場所を作る。
// 自分より高い優先度しか鳴っていなければ、その SE は鳴らさない。
// ノイズ(爆発など)は本数が別枠。new MMSXXEngine(canvas, { maxNoise: 2 }) で決める
// (既定 1 = 実機の PSG と同じ。数えるのは SE のぶんだけで BGM のドラムは別)。
// あふれたときは優先度の低いノイズ SE を止める。
// **実機と同じ音程のずれ**を出す(既定 true)。
// 実機はクロックを 16(三角波は 32)と整数で割った高さしか出せないので、
// 出せる音程が階段になる。低い音はほぼ合い、**高い音ほど狂う**
// (A6 で -12 セント、C7 で +14 セントほど)。
// **FM とノイズには効かない**(実機の FM は 1 オクターブを 512 段階で刻むので正確)。
// MSX の PSG / ファミコンの矩形波 / PC エンジン / SCC は同じ階段になる。
// URL からは ?psgtune=0 で消せる
mmsxx.audio.psgTune = false;              // まっすぐな音程にする
mmsxx.audio.psgTune = [true, false, true]; // チャンネルごとに決める
mmsxx.audio.playSE('shot');                       // ふつうの SE
mmsxx.audio.playSE('laser', 3);                   // 大事な SE
mmsxx.audio.playSE('fanfare', 9, { exclusive: true }); // 独り占め(他を全部止める)
mmsxx.audio.stopSE();

// ---- しゃべる (TALK) ----
// 録音データは持たない。鳴らすときに**フォルマント合成**で波形を作る。
// 音源(インパルス列 / ノイズ) -> 共鳴器 3 つ(母音の口の形) という組み立て。
// カタカナ(ひらがなも可)を渡すとモーラに分けて並べる。
// 空白と句読点は間になり、「ー」は伸ばし、「ッ」は詰まる。
mmsxx.audio.defineTalk('king', 'ワタシハ ウチュウノ テイオウ コゾリテ。');
mmsxx.audio.playTalk('king', 5);       // 第2引数は SE と同じ優先度
// 既定はわざと粗い(8 ビット機の声にする)。オプションで変えられる:
//   rate  書き出すサンプリング周波数(既定 8000)。低いほど粗い
//   bits  量子化ビット数(既定 6)。低いほどざらつく
//   pitch 声の高さ Hz(既定 120) / speed しゃべる速さ(既定 1)
//   fall  語尾へ向かって下がる量(半音。既定 3) / growl だみ声(既定 0)
mmsxx.audio.defineTalk('boss', 'タオサレハセン', { pitch: 92, bits: 4, growl: 0.7 });
// 作った波形は名前ごとにキャッシュされる(2 回目からは作り直さない)。

// ---- 入力 ----
mmsxx.input.isDown('ArrowLeft');       // KeyboardEvent.code で指定
mmsxx.input.wasPressed('Space');       // このフレームで押されたか
mmsxx.input.repeat('ArrowDown');       // 一覧の行送り(押した瞬間 1 回 → 待ち → 連続)
mmsxx.input.heldFrames('ArrowDown');   // 押しているコマ数(押していなければ -1)
mmsxx.input.press('Space');            // 押されたことにする(タッチから流し込む用)
mmsxx.input.release('Space');          // 離されたことにする

// ---- メインループ ----
mmsxx.run((m) => { /* 60fps で呼ばれる */ });
mmsxx.stop();
mmsxx.step(n);                         // デバッグ用に n フレーム手動で進める
```

## 入力の読みかたは 3 つ

| 読みかた | いつ true | 使うところ |
|---|---|---|
| `isDown(code)` | 押しているあいだずっと | 自機の移動 |
| `wasPressed(code)` | 押した瞬間の 1 コマだけ | 決定・ページ送り |
| `repeat(code, delay, gap)` | 押した瞬間に 1 回 → `delay` 待ち → `gap` おきに | 一覧の行送り |

`repeat` は**押している長さから歩数を出す**ので、呼ぶ側が数を覚える必要がありません。
同じキーを別々の場所から聞いても干渉しません。既定は `delay = 20`（約 0.33 秒）/
`gap = 4`（毎秒 15 歩）。

初動を待たせるのは**1 行だけ動かせるようにする**ためです。待ちが無いと、
ちょっと押しただけで数行飛んでしまいます。

タッチのフリックを「N コマ押しっぱなし」として `press()` / `release()` で流し込めば、
画面側は何も変えずに勢いのぶんスクロールします（[SMARTPHONE.md](SMARTPHONE.md)）。

## 直前の画面を溜める

**色番号のまま**輪っかに溜めておいて、あとから「何秒前の画面」を取り出せます。

```js
mmsxx.keepFrames(3);        // 直前 3 秒ぶんを持ちつづける
mmsxx.frameAgo(1);          // 1 秒前にいちばん近いコマ(canvas)
mmsxx.frameAgo(1, 2);       // 2 倍に広げて取り出す(ドットはぼかさない)
mmsxx.frameBackCanvas(0);   // 番号で取り出す(0 = いちばん新しい)。再生に使う
mmsxx.frameCount;           // いま持っているコマ数
mmsxx.keepFrames(0);        // やめて捨てる
```

**1 ドット 1 バイト**なので、色に直したものより 4 分の 1 で済みます。
264x200 なら 1 コマ 51.6KB、**60fps で 3 秒でも 9.1MB** です。

| 使いみち | やりかた |
|---|---|
| シェアに載せる 1 枚 | `frameAgo(1)` で「まだ無事だったころ」を取る |
| やられる直前のリプレイ | 溜まっているコマを頭から流す |
| 動画 | 取り出した canvas を並べて書き出す |

**写すのは色に直す前の 1 回のコピーだけ**なので、60fps でも落ちません。
色は取り出すときに引き当てるので、**色合いを切り替えていれば取り出した絵も新しい色**になります。

遊んでいないあいだは `keepFrames(0)` で捨てて、持ちっぱなしにしないこと。

**画面の大きさを変えると、溜めたコマは作り直されます**（大きさが変わったコマから
順に置き換わる）。切り替えた直後の数コマは前の大きさのものが混じるので、
そこで取り出すなら `keepFrames()` を呼び直して捨てるのが確実です。

### 音も溜められる

```js
mmsxx.keepSound(3);              // 直前 3 秒ぶんの音
await mmsxx.audio.soundBack();   // 溜まっているぶん(AudioBuffer)
mmsxx.audio.playSound();         // そのまま鳴らす(リプレイ用)
mmsxx.keepSound(0);              // やめて捨てる
```

生の波形なので符号化は要らず、**48kHz・モノラルの 3 秒で 0.6MB** ほどです。
輪っかは AudioWorklet の中に置いてあるので、毎コマのやりとりは起きません。
節の中身は文字列から作るので、**ファイルは増えません**。

**拾うのはミュートの手前**です。音を切って遊んでいても、
残した音にはちゃんと鳴っていたものが入ります。

### ポーズ中は止める

```js
mmsxx.holdCapture(true);    // 溜めるのを止める(溜めたものは捨てない)
mmsxx.holdCapture(false);   // 再開
```

**ポーズ中も画面は描き続けている**ので、止めないと輪っかが
「止まった画面」と「無音」で埋まり、**やられる直前の数秒が消えます**。
絵と音の両方に効きます。

### 溜めたコマを再生する

```js
mmsxx.playFrames({ layer: 5, seconds: 3, onEnd: () => 次へ進む() });
mmsxx.stopFrames();     // 途中でやめる(キーで飛ばすとき)
mmsxx.replaying;        // いま流しているか
```

指定したレイヤーへ 1 コマずつ写します。**そのレイヤーは再生に占領される**ので、
空いているもの(いちばん手前など)を渡してください。
溜めるのは自動で止まり、終わると元へ戻ります。

- **ゲームの状態はいっさい動きません。** 絵を写しているだけです
- `fps` を下げるとゆっくり流せます(既定 60 = 溜めたまま)
- `loop: true` でくり返します
- 透明(0)は背景色に置き換えるので、下のレイヤーは透けません

### 録画する

いまの画面を、そのまま動画にします。

```js
mmsxx.startRecord({ scale: 2, bitrate: 'high', border: 4, aspect: '16:9' });
const blob = await mmsxx.stopRecord();   // video/mp4(作れない環境では webm)
mmsxx.recording;                         // いま録っているか
mmsxx.recordKind;                        // 'mp4' か 'webm'
mmsxx.recordSize;                        // できたものの大きさ
```

- **キャンバスの中身**を録るので、ウィンドウが隠れていても録れます
- **音は出口の手前から拾います。** ミュートで遊んでいても動画には入ります
- `scale` は整数倍。**2 倍で録っておく**と、見る側が広げてもドットの角が溶けません
- `bitrate` は `BITRATE.low` / `mid`(既定) / `high` / `max` / `auto`、または数
- `type: 'webm'` で入れものを選べます(既定は mp4)

**枠は画面と別に決められます。**

```js
mmsxx.startRecord({ border: 0 });          // ボーダー無しで録る
mmsxx.startRecord({ border: 4, aspect: '16:9' });  // 黒で余白を足して 16:9 に
mmsxx.capture({ border: 4 });              // 静止画も同じ指定で
```

- `border` … 動画のまわりに残すボーダーの太さ(省略すると画面と同じ)
- `aspect` … `'16:9'` `'4:3'` `'1:1'` `'9:16'` か数(16/9)。**足りないぶんは黒で埋めます**
- **画面には出ません。** 遊んでいる人には見えず、ファイルの中だけが変わります
- まわりの黒はこちらで塗るので、**被弾フラッシュの白は持ち込みません**
- **録りはじめに決めて固定**します(途中で変えると動画が壊れるため)

重さを決めてあれば、余白を足してもファイルはほとんど大きくなりません
(真っ黒で動かないところは、符号をほとんど食わないため)。

### GIF アニメにする

```js
import { makeGif, saveGif } from './engine/util/gif.js';

const blob = makeGif(mmsxx, { seconds: 3, fps: 30 });   // image/gif
saveGif(blob, 'play.gif');
```

**溜めたコマはすでに色番号**なので、GIF と相性がとてもよいです。
ふつういちばん面倒な「色を減らす」工程が要らず、15 色は 4bit に収まります。
圧縮(LZW)も含めて**外の部品は使いません**。

| 中身 | 実測(264x200・3 秒・30fps) |
|---|---|
| 大きさ | **155KB** |
| 作る時間 | **72 ミリ秒** |
| コマ数 | 90(ずっとくり返す) |

**音は入りません**(GIF に音は無い)。音つきが要るなら別の道になります。
待ち時間は 1/100 秒きざみなので、**30fps(待ち 3)を勧めます**。

## 種つきの乱数

**同じ種なら、いつでも同じ順番で同じ数が出る。**
プレイの再現（操作の記録から作り直す）と、途中の状態の保存に使う。

```js
mmsxx.rng.seed(12345);          // 親の種を決める(記録に残すのはこれだけ)
mmsxx.rng.masterSeed;           // いまの親の種

const r = mmsxx.rng('boss');    // 名前つきの流れ(同じ名前なら同じもの)
r.next();                       // 0〜1
r.int(0, 5);                    // 0..5 の整数
r.pick(['a', 'b', 'c']);        // ひとつ選ぶ
r.chance(0.25);                 // 4 回に 1 回くらい true

mmsxx.rng().next();             // 名前を省くと既定の流れ('main')
```

**名前ごとに別の流れ**になるので、片方が 1 回多く引いても、もう片方はずれない。
ステージのコードを直してもボスの引く数列は変わらないので、
作っている最中に「ボス戦だけ同じ条件でくり返す」ができる。

**どこまで分けるかはゲームが決める。** 名前なしを 1 本使うだけでもよい。
流れの種は**親の種と名前から作る**ので、あとから流れを増やしても
古い記録が読めなくなることはない。

| 口 | 意味 |
|---|---|
| `mmsxx.rng(name?)` | 名前つきの流れを返す（省略すると `'main'`） |
| `mmsxx.rng.seed(n?)` | 親の種を決める（省略すると時計から）。作ってある流れも作り直す |
| `mmsxx.rng.masterSeed` | いまの親の種（記録に残す値） |
| `mmsxx.rng.names` | 作ってある流れの名前 |
| `mmsxx.rng.reset(name?)` | 種から作り直す（名前を省くと全部） |
| `mmsxx.rng.saveAll()` / `restoreAll(data)` | 全部の状態を写す・戻す（途中の状態の保存） |
| `r.save()` / `r.restore(state)` | 1 本ぶんの状態を写す・戻す |

### 使い分け

**見た目だけのものは `Math.random()` のままでよい。** 爆発の粒、画面揺れ、
背景の賑やかしはずれても困らない。**ゲームの結果に効くところだけ**こちらへ移す。

### 気をつけること

流れを分けても、**操作の記録が版をまたいで再生できるようにはならない**。
敵の出かたが変わればプレイヤーの位置が変わり、結果は別物になる。
記録には版番号を添えて、**違う版なら再生を断る**こと。

## 1 行に出せるスプライトの数

実機の VDP は**1 走査線に決まった枚数**しか出せず、あふれたぶんは
その行だけ消えます(MSX1 = 4 枚 / MSX2 = 8 枚)。消えるのは優先度の低いほうで、
単位は「スプライト」ではなく「**行**」です。

```js
mmsxx.spriteLimit = 4;      // 1 行 4 枚まで(0 = 無制限。既定)
mmsxx.spriteRotate = true;  // 同じ優先度のものはコマごとに順番を回す
```

枚数は自由に決められます。4 や 8 でなくてもかまいません。

数えるのは**そのコマに実際に出ているものだけ**です。`visible` が false のもの、
`blink` で消えているコマのものは席を取りません
(実機で画面外へ逃がしたスプライトが席を取らないのと同じ)。
そのため、点滅を使っているところでは**そもそも混みにくく**なります。

**BG スプライトは数に入れません。** このエンジン独自の仕組みなので、ちらつかせません。

`spriteRotate` は、あふれたときに**いつも同じものが消えないように**するためのものです。
同じ優先度のものを 1 コマずつ順ぐりに入れ替えるので、
「1 枚が消えっぱなし」ではなく「みんなが少しずつちらつく」形になります。
実機のゲームが並べ替えでやっていたことと同じです。

`blink` とは別のものです。`blink` は**狙ってやる点滅演出**、
こちらは**混みぐあいの再現**。両方いっしょに使えます。

### 画面ぜんぶの枚数

実機は置ける枚数そのものが決まっています(MSX は 32 枚)。

```js
mmsxx.spriteMax = 32;   // 画面に 32 枚まで(0 = 無制限。既定)
```

あふれたものは**まるごと出ません**(1 行の制限と違い、行単位ではない)。
`spriteRotate` を入れておけば出るものが順ぐりに入れ替わるので、
消えっぱなしにはなりません。1 行の制限といっしょに使えます。

### 席の取り合いでの強さ

消える順は `priority`(描く前後)とは**別に**決められます。

```js
sp.rank = 'always';   // あぶれない。席は取るので、ほかを押しのける
sp.rank = 'strong';   // 先に席を取る(混んでも残りやすい)
sp.rank = 'weak';     // 既定
sp.rank = 'last';     // 取り合いになったら譲る。空いていれば出る
```

「手前に描くが、消えるのは真っ先」といった書きかたができます
(自機の弾など)。同じ強さのものどうしは `spriteRotate` で順番が回ります。

### 処理落ち

実機は「1 コマのうちに描き切れないと、次の割り込みまで待たされる」ので、
画面が混むと**動きがそろって遅くなります**。あれを狙って起こせます。

```js
mmsxx.slowAt = 24;        // スプライトがこの数を超えたら落とす(0 = しない)
mmsxx.slowMode = 'soft';  // 'hard'(既定) / 'soft'
mmsxx.slowFps = 30;       // 'hard' のときの落ちた先(既定 30)
mmsxx.slowSoft = 0.02;    // 'soft' の重さ(あふれ 1 枚あたり)
mmsxx.slow;               // いま落ちているか(見るだけ)
```

- **`hard`** … 超えたとたんに `slowFps` まで落ちます。アーケードの
  「はっきり半分になる」感じ(わざとそうしていた作品も多い)
- **`soft`** … **混みぐあいに応じて、ときどき 1 コマ落とします**。
  少し超えただけなら たまにつっかえる程度、混むほど回数が増えて
  半分の速さへ近づきます。MSX の実機で起きていた
  「微妙に遅くなる」ほうに近い見えかたです

`soft` は続けて 2 回は落としません。いくら混んでも半分で止まります。

数えているのは BG スプライトも足した数(`vdp.shownSprites`)です。

### スプライトを大きくする

```js
sp.mag = 2;   // 1 ドットが 2x2 になり、16x16 の絵が 32x32 で出る
```

1 ドットを四角に置き換えるだけなので、**角は溶けません**。置く位置は左上のまま。
実機は VDP のビット 1 つで全部のスプライトが同時に大きくなりますが、
ここは 1 枚ずつ決められます。**当たり判定はゲームが持つ**ので、
大きくしたぶんはゲーム側でも見てやること。

### 文字を大きくする

```js
layer.print(x, y, 'REPLAY', 8, 1, 2);   // 最後の 2 が倍率(16x16 の字)
```

同じ字を太らせるだけで、別の書体を持つわけではありません。

## 反転と回転

1 枚の絵から向き違いを作れます。変換結果はキャッシュされるので、
毎フレーム参照しても作り直しは起きません。

### 素材づくりの小道具

`assets-src/makedata.mjs` には MML を半音単位で移調する `transposeMML(mml, n)` があります。
曲のキーを変えたいときは、書き直さずにこれを通します。

| 対象 | 左右反転 | 上下反転 | 90 / 270 度 | 180 度 |
|---|---|---|---|---|
| 通常スプライト | ○ | ○ | ○ | ○ |
| BG スプライト | ○ | ○ | × | ○ |
| レイヤーへの描画 | ○ | ○ | × | ○ |

90/270 度は「横 8 ドット 2 色」が縦方向の制約に変わってしまうため、BG では使えません
(指定しても無視されます)。

## 音のあつかい

```js
mmsxx.audio.mute(true);        // 消す(曲は止めずに出口を閉じるだけ)
mmsxx.audio.muted;             // いま消えているか
mmsxx.audio.volume = 0.7;      // 大きさ(0〜1)。曲も効果音もまとめて動く
mmsxx.audio.maxTalk = 2;       // 同時に鳴らせるセリフの数(既定 1)
```

`mute()` と `volume` は別のものです。**溜めるほうは絞らない**ので、
音を消して遊んでいても、残した音や録画にはちゃんと鳴っていたものが入ります。

### 効果音の席を種類ごとに取っておく

優先度だけで譲り合わせると、**先に鳴っていた音が場所を握ったまま**になり、
撃つ音が鳴りつづけているあいだ、当たった音や爆発が聞こえなくなります。

```js
mmsxx.audio.reserveSE({
  shot: { voices: 2, noise: 1, names: ['shot'] },
  hit: { voices: 6, noise: 2, names: ['hit', 'boom', 'bigboom'] },
});
```

- **取っておいた席は、そのカテゴリの中だけで取り合います**
- `names` に書いておけば、鳴らす側は今までどおり(`playSE('boom', SE_HIT)`)。
  その場で決めたいときは `playSE('boom', SE_HIT, { ch: 'hit' })`
- カテゴリを指定しない音は**残りの席**を使い、そこは優先度で取り合います
- 同じ優先度どうしでは**あとから鳴らしたほうが勝ちます**(実機と同じ)

## MML リファレンス

MSX BASIC の PLAY 文風です。

| コマンド | 意味 |
|---|---|
| `c d e f g a b` | 音符。直後に `+`/`#`(半音上げ)、`-`(半音下げ)、数字(音長)、`.`(付点) |
| `r` | 休符 |
| `o<n>` | オクターブ 1..8 (`o4` の `a` = 440Hz) |
| `>` `<` | オクターブ上げ / 下げ |
| `l<n>` | デフォルト音長 (4=四分音符) |
| `t<n>` | テンポ (四分音符/分) |
| `v<n>` | 音量 0..15 |
| `q<n>` | ゲート 1..8 (8=フルレングス、スタッカート表現用) |
| `&` | タイ (直後の音符の長さを直前の音に足す) |
| `[ ... ]<n>` | 繰り返し (n 省略時 2 回、ネスト可) |
| `@<n>` | 波形 0..7 |
| `@{名前}` | 波形を名前で(**こちらを勧める**) |
| `@e<n>` | エンベロープ 0..5 |
| `@e{名前}` | エンベロープを名前で(**こちらを勧める**) |
| `@d<n>` | デチューン(重ねる音のずれ。0 で無効) |
| `@v<n>` | ビブラート(0 で無効) |
| `@s<n>` | エコー(0 で無効) |

波形は `@0`〜`@3` がパルス(デューティ 12.5 / 25 / 50 / 75%)、`@4` 三角波、
`@5` ノコギリ波、`@6` サイン波、`@7` ノイズです(旧記法の `@n` もノイズ)。

**番号ではなく名前で書けます。** 番号はエンジンの都合で動くことがあるので、
ゲーム側からは名前で指すほうが安全です。

```
@{pulse50} @e{piano} cde      // 名前で(勧める)
@2 @e3 cde                    // 番号で(同じ音)
```

使える名前は、波形が `pulse12` `pulse25` `pulse50` `pulse75` `triangle`
`saw` `sine` `noise`、エンベロープが `flat` `soft` `percussive`
`piano` `pad` `pluck` です。知らない名前を書くと、console に
**使える名前を並べて**知らせ、その指定だけ無視します(曲は鳴りつづけます)。

MSX 実機(AY-3-8910)の矩形波は**デューティ 50% 固定**なので、
実機に寄せるなら `@{pulse50}` だけを使うことになります。

```js
mmsxx.audio.defineBGM('main', [
  't150 q7 v12 l8 @1 @e1 @s3 o5 [cdefgab>c]2',   // メロディ (25%パルス+エコー)
  't150 q8 v12 l8 @4 @e0 o2 [c>c<c>c<c>c<c>c]2', // ベース (三角波)
  '@7 @e2 t150 l8 [v12o2c v6o6c v10o4c v6o6c]4', // ドラム (ノイズ)
]);
```

トラックの長さがそろっていないとループでずれます。`npm run checkbgm` で全曲を確認できます。

## アセットの作り方

`assets-src/makedata.mjs` にドット絵・曲・出現テーブルを**コードとして**書き、
`npm run data` で `game/gamedata.js` を生成します。

生成時に**絵素材のチェック**が走ります(警告のみでビルドは止まりません)。

- BG 素材: 横 8 ドット 2 色(背景色込み)に違反していないか
- スプライト素材: 3 色以上を使っていないか、サイズが 8 か 16 の倍数(64 まで)か

`BG_IMAGES` に入れた絵は、書き出す前に**自動で「行ごとに 2 色」へ均されます**。
BG に描く絵をここへ入れ忘れると、素材が制約を破ったまま出てしまいます
(実行時はエンジンの検査が見つけます)。

### コツ

- **BG 素材は「行ごとに違う 2 色」を積極的に使う**と中間色に見えて豪華になります。
  市松模様はルール違反になりがちなので使いません
- 大きなメカは 8x8 のタイル(装甲板・継ぎ目・ボルト・排気口・関節・シリンダー・
  センサー・警告ストライプ・面取りなど)を組み合わせて作ります
  (`MECH_TILE` と `buildMech()`)。1 タイル 2 色なので制約が自動的に守られ、
  パーツごとに色を変えられます
- 反転で済むものは素材を持たず、`flipX` などで向きを変えます

## 速さについて

- 1 フレーム(更新 + 合成)は実測 **0.5ms 前後**(PC。16.7ms の予算に対して 3% ほど)
- 重いのは画面の合成で、そのうち 8 割ほどを占める
  (256x192 の全ピクセルをレイヤーの枚数ぶん走査するため)
- 合成は**パレット番号(1 バイト)のまま**行い、色(4 バイト)に直すのは最後の 1 回だけ。
  重なった回数ぶん色を引かずに済む(実測 0.82ms → 0.69ms)
- canvas は**等倍**で持ち、拡大は CSS にまかせる。
  実際の画素で整数倍になる大きさを選ぶので、ドットの大きさがまだらにならない
- **何も描かれていないレイヤーは合成そのものを飛ばす**ので、
  使っていないレイヤーを持っていても無駄にならない
  (全レイヤーが空なら 0.53ms → 0.11ms)

## 制限・メモ

- 音はブラウザの制約により、最初のキー入力以降に有効化されます
- `window.mmsxx` は**開発版のビルドのときだけ**公開されます(`mmsxx.expose()`)。
  `mmsxx.stop()` のあと `mmsxx.step(n)` で手動フレーム送りができます
- ブラウザのタブが非表示のあいだは `requestAnimationFrame` が止まるため、
  自動テストで進めたいときは `stop()` + `step(n)` を使ってください
