# スクロールの差の考察（M-0 ⑥）

**まだ作らない。** どこが「あとで死ぬ」かだけ先に見きわめる。
2026-08-22 時点。[TODO.md](TODO.md) の M-0 ⑥ から来た。

前提は ④（当たりの丸め）と同じ形。
**見た目と論理で別々に丸めを持つと、片方だけ直したときに黙って食い違う。**
④ では当たりで実際に起きかけていた。スクロールでは**まだ**起きていない ——
このゲームは世界が動かず、背景は飾りだからだ。次のゲームで起きる。

## いまどうなっているか

レイヤーごとに `snap` を持っている（`engine/video.js`）。

| | 値 | 意味 |
| --- | --- | --- |
| `layer.snap = 0` | 既定 | 滑らかに動かす |
| `layer.snap = 8` | | 表示を 8 ドット単位に量子化する |

STAR FABLE は星空 3 枚と `neb` の 4 枚に `8` を入れている（`game/main.js:578`）。
速さはレイヤーごとの小数（`-0.25` / `-0.9` / `-2.0`）。

揺れは**別の口**で、`mmsxx.setAdjust()`。画面全体を **1 ドット単位**でずらす
（実機の SET ADJUST 相当）。こちらは丸めない。
8 ドットで動く背景の上に 1 ドットの揺れが乗るのは、実機でもそうなので正しい。

## 1. 「8 ドットかどうか」の 1 つの数では足りない

機械ごとに、粒度がそもそも一様ではない。

| 機械 | 縦 | 横 |
| --- | --- | --- |
| MSX1 | レジスタが無い。名前テーブルを書き換えるので実質 8 ドット | 同じく 8 ドット |
| MSX2 | **1 ライン単位**のレジスタがある | 8 ドット単位 ＋ adjust で ±7 |
| ファミコン | 1 ドット | 1 ドット（ただし属性は 16 ドット単位） |
| PC-88(V1) | テキストは行単位、グラフィックは実質なし | — |

**MSX2 だけで縦と横の粒度が違う。**いま `snap` は 1 つの数なので、この機械を
そのまま表せない。分けるなら `snapX` / `snapY`。これは安い。

## 2. 論理の位置と、見えている位置がずれている

`scrollX` / `scrollY` は**小数のまま**持っていて、丸めているのは `render()` の中だけ
（`engine/video.js:1970`）。だから

- ゲームが読める `scrollY` … 小数。滑らか
- 実際に描かれている位置 … 8 の倍数

が**最大 7 ドットずれる**。そして**描かれている側を読む口が無い**。

このゲームは背景が飾りなので誰も困らない。困るのは世界がスクロールするゲームだ。
敵をワールド座標で置いて画面座標に直すとき、丸めた scroll で引かないと、
**敵だけが 1 ドット単位で滑って背景と食い違う**。そのときゲーム側に
`Math.floor(scrollY / 8) * 8` を書くことになる —— ④ で消したばかりの写しが、また生える。

**打つ手**: 描かれている位置を読む口をエンジンが出す（`layer.viewX` / `viewY`）。
式は `snapTo()` が既に持っているので、新しく書くものは無い。安い。

## 3. 丸める場所が `render()` の中にある

いまは合成しながら丸めている。つまり**画面を描かないと丸めた値が決まらない**。
ヘッドレスで回帰試験を取るとき、これは ④ と同じ形の穴になる
（世界がスクロールするゲームでは、scroll は飾りではなく進行の値になる）。

**打つ手**: 丸めるのは `scroll()` を書いた時点か、読み出しの口で。
`render()` は決まった値を使うだけにする。中くらいの手間。

## 4. 誰が `snap` を決めるのか

④ で線を引いた ——「**見た目は機械、当たりはゲーム**」。
スクロールの丸めは**機械の側**にある。
いまゲームが `far.snap = 8` と 4 行書いているのは、⑤ の機械プロファイルが無いからで、
本来の持ち主ではない。

⑤ が入ったら、`snap` の既定は機械から来て、ゲームは**視差の速さだけ**を言う形にする。
**逆にしない**（ゲームが機械の都合を宣言する形にすると、機械を替えるたびに全ゲームを直す）。

## 5. 回り込む周期が、裏画面の大きさに溶接されている

**表示画面（256 x 192）の話ではない。裏画面＝仮想 VRAM の話。**
レイヤーごとに持っている絵の入れ物のことで、STAR FABLE は **256 x 1024** を取っている
（横は画面ぴったり、縦に長くとってスクロールさせる。`game/main.js:123`）。

大きさはレイヤーごとに宣言できる。ただし `checkVirtualSize()` が効いていて、
**いまは 2 のべき乗（1, 2, 4 … 256, 512, 1024）しか通らない**（320 は落ちる。8 の倍数では足りない）。

```
virtualWidth は 256〜2048 の 2 の冪で指定してください (指定値: 320)
```

しばりの理由は**セルではなく添字の作りかた**にある。8 x 8 のセル（`cellW = w >> 3`）は
8 の倍数でありさえすればよく、320 なら 40 マスで何も困らない。落ちるのは 3 か所。

| 場所 | いま | 320 だと |
| --- | --- | --- |
| 行の先頭 | `(vy & maskY) << shift` | `shift = log2(320) = 8.32`。**整数でない** |
| 添字の合成 | `rowBase \| vx` | OR は境界がそろっている前提。**ずれる** |
| 端の回り込み | `vx & maskX` | **周期が合わない** |

**外すのは安い。**行の先頭を `(vy % h) * w`、合成を `rowBase + vx` にして、
回り込みは引き算で戻す。`\|` を `+` にするのはただだし、行の先頭は 1 行に 1 回なので
掛け算でも効かない。**画素ごとに残るのは `& maskX` を比較に替えるところだけ**。

そもそもこのしばりは、**GPU に載せるなら 2 のべき乗が好ましい**という見込みで
決めたものらしい。ところがいまの合成は **CPU で回している** ——
`engine/` に WebGL もテクスチャも 1 つも出てこない。canvas は `2d` だけで、
`Uint8Array` を JS のループで舐めて `putImageData` している。
**つまりこのしばりが買っているものは、`&` と `<<` の速さだけ**。

### ビット演算はどこで効いているのか

**効く場所は 1 か所しかない。**レイヤー合成の「画素ごとに舐める道」
（`render()` の中の、まばらでないほうの枝）。

- **星 3 枚だけがこの道を通る。**セルが 100% 埋まっているので、飛ばす判定が丸損になり
  `sparse` にならない
- `neb` は**セル飛ばし**の道（埋まり 1%）。あちらは折り返しが **8 画素に 1 回**しか出てこない
- スプライトはこのループを通らない
- 行の先頭の `<< shift` は **1 行に 1 回**（1 コマで 576 回）。掛け算にしても差が出る量ではない

実物と同じ条件で測った ——
裏画面 256x1024、画面 256x192、星 3 枚、絵の埋まりは 20% / 13% / 6%、
`scrollX` は 3 枚とも **0**（このゲームは横に流していない）。

| 作り | 星 3 枚で | A 比 | 1 コマ(16.7ms)のうち |
| --- | --- | --- | --- |
| **A** いまの作り（`& mask` と `<< shift` と `\|`） | 0.355 ms | 1.00 | 2.1% |
| **B** べき乗をやめる（行は掛け算、横は引き算で戻す） | 0.436 ms | 1.23 | 2.6% |
| **C** 端で 2 本に割る（画素ごとの折り返しを無くす） | **0.313 ms** | **0.88** | 1.9% |
| **D** **画素ごとに**べき乗かどうかを見る | 0.481 ms | **1.36** | 2.9% |
| **E** **レイヤーごとに 1 回**見て道を選ぶ | 0.356 ms | 1.00 | 2.1% |

読みどころは 3 つ。

- **ビット演算は確かに速い（B は 1.23 倍かかる）。ただし 2.1% が 2.6% になるだけ。**
  しばりが買っているのは 1 コマあたり 0.08 ms
- **D — 画素ごとに「べき乗か?」を見ると、判定のぶんで 1.36 倍。
  しばりを外すよりも遅くなる。**分岐は**レイヤーごとに 1 回**なら（E）ただ
- **C はいまより速い（0.88 倍）。**しかもべき乗を要らない

### 効いていたのはビット演算ではなかった

C が A に勝つのは、ビット演算をやめたからではない。
**A は `L.maskX` と `L.shift` を画素ごとにプロパティから読んでいる。**
C の内側は局所変数と `pixels` しか触らない。
1 コマで 147,456 回まわる場所なので、そこが出た。

つまり**この合成で効く順**はこうなる。

1. 画素ごとのプロパティ読みを外へ出す
2. 画素ごとの分岐を外へ出す
3. …ずっと下がって、ビット演算かどうか

**2 のべき乗しばりは 3 番目のためのもの**で、1 と 2 を直せば逆転する。

> 測ったのは Node の中のループだけ。**実物の合成はヘッドレスでは測れない** ——
> `render()` は画面が無いと合成を飛ばすようにしてある（試験を速くするため）。
> ブラウザで採るなら `mmsxx.vdp.profile = true`。

「2 のべき乗でない周期が欲しい」と思ったその日に外せばよく、
**先に決めておくことは何も無い**。ここは記録だけ。

### ほかにべき乗で縛るとよさそうなところは、いまのところ無い

**べき乗が効くのは、画素ごとにまわるループから仕事を減らせるときだけ。**
このエンジンで画素ごとにまわるのは 2 か所しかない。

| どこ | 1 コマの画素数 | べき乗で得するか |
| --- | --- | --- |
| レイヤー合成 | 147,456（星 3 枚 x 256x192） | 上のとおり。2% の中の話 |
| スプライト描画 | 8,000 くらい（16x16 が 32 枚） | **合成の 5%**。縛っても見えない |

そのほか（コマ溜めの輪、音の席、セルの格子）は
**1 コマに 1 回**か**1 行に 1 回**しか通らないので、何倍速くしても表に出ない。

むしろスプライト描画のほうには **D と同じ形**が入っている ——
`(mag === 1) ? dx : (dx / mag) | 0` を**画素ごとに**見ている。
直すならこちらで、べき乗の話ではない。

## 6. 速さと丸めの噛み合わせ

`snap = 8` で小数の速さを与えると、**絵が動く間隔は割り切れないかぎり不揃いになる**。
いまの 3 枚を数えるとこうなる。

| レイヤー | 速さ | 1 マス動く間隔（コマ） |
| --- | --- | --- |
| `far` | -0.25 | 32, 32, 32, … |
| `mid` | -0.9 | 9, 9, 9, 9, 9, 9, 9, 9, 9, **8**, … |
| `near` | -2.0 | 4, 4, 4, 4, … |

`mid` だけ 10 回に 1 回つまる。実機でもこう見えるので不具合ではない。
ただし **`snap = 0` の機械に移すと `mid` だけ印象が変わる**（ほかは割り切れるので変わらない）。

**速さは、きれいに見えるものを目で選ぶ。**「何コマで 1 マス」のような宣言の口は要らない
（作りかけたが、やめる）。機械を替えて印象が変わったら、そのときまた目で選べばいい。

`snap` に実際に入る値は **ふつう 1 か 8。2 もあり得る**。
`0`（滑らか）と `1`（1 ドット単位）は別物であることに注意 ——
`0` は `Math.round()`、`1` は切り捨てになる。

## 7. 入れないと決めるもの

**名前テーブルを書き換えて動かす**（MSX1 の本当のやり方）は**やらない**。
重いし、ここまでやっても得られるのは「速いスクロールができない」という制約だけ。
演出として欲しくなったらそのとき個別に書く。標準の口にはしない。

⑥ に書いた「**無理はしない**」はこれのこと。

## まとめ —— 先にやる順

**あとで高くつくのは、④ と同じ形をしている 2 つだけ。**
どちらも「見た目と論理で丸めが 2 つある」から起きる。

1. **丸める場所を `render()` の外へ出す**（3）。
   いまは画面を描かないと丸めた値が決まらない。
   世界がスクロールするゲームでは、これがそのままヘッドレス試験の穴になる。
   **ゲームを書き始めたあとで動かすと、そのゲームの挙動が変わる**
2. **描かれている位置を読む口**（2）。無いままだと
   `Math.floor(scrollY / 8) * 8` がゲーム側に生える。④ で消したのと同じ写しが、
   **ゲームの数だけ増える**

以下は、必要になってからで値段が変わらない。

3. `snapX` / `snapY` に分ける（1）。MSX2 のため
4. `snap` の持ち主を機械へ移す（4）。⑤ 待ち
5. 2 のべき乗でない裏画面（5）。**先に決めることは無い**。欲しくなった日に外す
6. 速さの宣言（6）は**やらない**。目で選ぶ

1 と 2 が済んでいれば、世界がスクロールするゲームを始めても死なない。
